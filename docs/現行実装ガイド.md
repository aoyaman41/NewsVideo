# 現行実装ガイド

このドキュメントは、2026-07-13 時点の `main` 実装に合わせた運用ガイドです。

## 1. 実行レイヤー

- `src/**` は Renderer（React UI）。
- `electron/main.ts` は Electron Main プロセス。
- `electron/preload.ts` は `window.electronAPI` のブリッジ層。
- `electron/ipc/*.ts` は Main 側の IPC ハンドラー実装。

## 2. 主要フロー

- プロジェクト保存・読込: `project:*`（`electron/ipc/project.ts`）
- 設定・APIキー: `settings:*`（`electron/ipc/settings.ts`）
- スクリプト生成: `ai:generateScript`（`electron/ipc/ai.ts`）
- 画像プロンプト生成: `ai:generateImagePrompts`, `ai:generateImagePromptForTarget`（`electron/ipc/ai.ts`）
- 画像生成: `image:generate`, `image:generateBatch`（`electron/ipc/image.ts`）
- 音声生成: `tts:generate`, `tts:generateBatch`, `tts:getVoices`（`electron/ipc/tts.ts`）
- 動画出力: `video:render`, `video:preview`, `video:cancelRender`（`electron/ipc/video.ts`）

## 3. モデル利用（現行）

- テキスト生成（スクリプト/画像プロンプト）:
- `gpt-6-astra` / `gpt-5.6-sol` / `gpt-5.6-terra` / `gpt-5.6-luna` / `gpt-5.4` / `gpt-5.2` / `gemini-3.1-pro` / `claude-opus-5-5`（設定で選択）
- 既定は `gpt-5.2`。GPT-5.6 系は、品質優先なら `sol`、品質と費用のバランスなら `terra`、費用または大量処理優先なら `luna` を目安にする
- GPT-5.6 系の推論強度は `none` / `low` / `medium` / `high` / `xhigh` / `max`。`minimal` は対応しない
- スクリプト生成と画像プロンプト生成で異なる OpenAI 系モデルを選ぶ場合、設定画面の推論強度は両モデルで共通して使える値だけを表示する
- どちらか一方でも OpenAI 系モデルを選んだ場合は `OpenAI` API キーが必要
- OpenAI の文章生成は引き続き Chat Completions API を使う。スクリプト生成は JSON Schema の Structured Outputs で応答形を検証し、OpenAI 側のリトライは SDK 内蔵処理に一本化する
- 使用量には取得できた範囲でキャッシュ読取・書込、推論トークン、APIリクエスト数も保存し、GPT-5.6 の概算料金へ反映する
- `claude-opus-5-5`（Claude Opus 5.5）はプロバイダ `anthropic` として扱い、どちらか一方でも選んだ場合は `Anthropic` API キーが必要。接続テストは公式 SDK の `models.retrieve('claude-opus-5-5')` で行う
- Claude は公式 SDK（`@anthropic-ai/sdk`）の Messages API を使う。thinking は常にオンのため `thinking` と `temperature` 等は送らず、思考の深さは `output_config.effort`（`low` / `medium` / `high` / `xhigh` / `max`、アプリの既定は `high`）だけで指定する。設定値は `claudeEffort`
- スクリプト生成はストリーミング（`max_tokens` 64000）と Structured Outputs（zod v4 スキーマ）で受け取り、それ以外は非ストリーミング（`max_tokens` 16000）。リトライは SDK 内蔵処理に一本化し、同時実行数は `anthropic` 枠で制御する
- `stop_reason` が `refusal` の場合は別モデルへフォールバックせずエラーを表示し、`max_tokens` の場合は途切れた出力を使わずエラーにする
- シーンごとの画像プロンプト一括生成では、共通のシステムプロンプトにプロンプトキャッシュ（`cache_control: ephemeral`）を付ける
- Claude の使用量は `inputTokens` にキャッシュ読取・書込を含めた合計を記録し、Opus 5.5 の単価（入力 $4 / 出力 $20 / キャッシュ読取 $0.20 / キャッシュ書込 $5、1M トークンあたり）で概算する
- 画像生成:
- `gpt-image-2.5-sunburst`（既定。新規設定のみ）/ `gpt-image-2.5-flare` / `gpt-image-2` / `gemini-3.1-flash-image` / `gemini-3-pro-image`
- Gemini の preview 版（`gemini-3.1-flash-image-preview` / `gemini-3-pro-image-preview`）は 2026-06-25 に提供終了。設定・プロジェクトの `generationConfig`・画像生成時に保存済みの preview 版の ID を GA 版へ読み替える（`normalizeImageModelId`）。過去の画像メタデータと使用量に記録された ID は書き換えず、料金表にも preview 版の行を残す。変更検知の指紋は読み替えの前後で同じ値になるため、読み替えだけで画像が更新対象にはならない
- `gpt-image-2.5-sunburst`（画質重視）/ `gpt-image-2.5-flare`（速度重視）/ `gpt-image-2` は OpenAI Images API と OpenAI キーを使う。モデルIDは日付なしのエイリアスを送り、選択中のモデルIDを生成メタデータと利用量に記録する。利用量はOpenAI画像カテゴリで記録し、テキスト入力と画像出力の料金（3モデル共通）を適用する
- サイズ（`getOpenAIImageDimensions`）と品質は3モデル共通。`xhigh` / `max` の品質は未対応
- Astraの推論強度は `low / medium / high / xhigh / max`、アプリでの初期値は `medium`
- TTS:
- `google_tts` / `gemini_tts` / `macos_tts`
- Gemini TTS のモデルは `gemini-3.8-flash-tts`（既定）/ `gemini-3.8-flash-lite-tts` / `gemini-3.1-flash-tts-preview` / `gemini-2.5-pro-preview-tts` / `gemini-2.5-flash-preview-tts` から選択できます。既定値の変更は新規設定のみに適用され、保存済みの `ttsModel` はそのまま使われます。
- 3.8 系は応答が RIFF ヘッダ付き WAV、3.1 以前はヘッダなし PCM です。保存時はモデル名ではなく応答データの先頭（`RIFF`）で判定し、PCM のときだけ WAV ヘッダを付けます。

## 4. 配信スタイルと締め文

- 記事画面では `project.presentationProfile` を持ち、プロジェクト単位で台本生成方針を保持します。
- 現在の preset は `news`、`explain`、`report`、`short` の4種類です。
- 各 preset は `tone`、`targetDurationPerPartSec`、既定の締め文を持ちます。
- 締め文は `preset / none / custom` で切り替えます。
- 音声の話し方は `news`、`explain`、`casual`、`promo` の preset で選び、短い補足文だけ上書きできます。
- `ai:generateScript` は `tone`、`targetDurationPerPartSec`、`closingLine` を受け取り、通常生成と記事画面の自動生成で同じ設定を使います。
- `presentationProfile` を持たない既存プロジェクトは `news + preset closing` として読み込みます。
- 一般化の境界定義は `shared/project/contentCustomization.ts` と [コンテンツカスタマイズ方針](./コンテンツカスタマイズ方針.md) を参照してください。

## 4.1 音声スタイルと app settings の分離

- `ttsEngine` と `ttsVoice` は app settings 側の既定値です。
- `presentationProfile.ttsNarrationStylePreset` と `ttsNarrationStyleNote` は project 単位の話し方設定です。
- Gemini TTS ではこの話し方 preset を instruction prompt として適用します。
  - 3.8 系（`gemini-3.8-flash-tts` / `gemini-3.8-flash-lite-tts`）は入力テキストを一字一句読み上げるため、本文には台本だけを入れ、指示は `speechMetadata.style` で渡します（`@google/genai` 1.x では `httpOptions.extraBody` 経由。`electron/utils/geminiTts.ts`）。
  - 3.1 / 2.5 系は従来どおり、指示を本文の前に連結します。

## 4.2 動画 outro と app settings の分離

- `presentationProfile.closingCardEnabled`、`closingCardHeadline`、`closingCardCtaText`、`sourceDisplayMode`、`sourceDisplayText` は project 単位の outro 設定です。
- 動画書き出しでは `opening video -> 各パート -> closing card -> ending video` の順で連結します。
- 書き出しとプレビューは、待ち行列の順番が来た後に保存済みの最新のプロジェクトを読み、それに対して作ります。リビジョンの一致は求めず、画面や自動生成が意図した書き出し内容（シーン構成・画像・音声・字幕・締めカード・縦横比、`shared/project/renderIntent.ts`）が最新と一致するかだけを確かめ、本当に違うときだけ `[RENDER_CONFLICT]` のエラーで止めます。画面は未保存の変更がなければ最新を読み直して 1 回だけ再試行します。Main でプロジェクトを保存したときは必ず `project:changed` を送ります。
- `settings.openingVideoPath` と `settings.endingVideoPath` は app 全体の共通素材パスで、動画画面では今回の書き出しに含めるかだけ切り替えます。
- closing card 内の出典行は `auto / hidden / custom` で切り替え、`auto` のときだけ記事の `source` を `出典: ...` 形式で表示します。
- `closing card` 系フィールドがない既存 project は互換性のため `closingCardEnabled = false` で読み込みます。

## 5. 画像スタイル方針

- 画像スタイルは `infographic`、`editorial`、`minimal`、`social`、`textRich`、`dataCard` の preset に限定します。
- project の `presentationProfile.imageStylePreset` と `presentationProfile.aspectRatio` を、画像プロンプト生成と画像生成の両方で使います。
- project の `presentationProfile.styleReferenceImageIds` は、画像画面で選んだ最大3枚のスライドサンプルを保持します。
- `presentationProfile.styleReferenceNote` は、参照サンプルから特に合わせたい点だけを短く補足します。
- 新規 project と、`aspectRatio` がない既存 project は app settings の `defaultAspectRatio` を初期値として使います。
- 画像 style の raw prompt 上書きはまだ advanced 扱いで、通常 UI には出していません。

## 6. 画像プロンプト生成方針（重要）

- 1回の長文抽出ではなく「1パートごとの抽出」を採用しています。
- バッチ時は最大10並列で抽出し、最終プロンプトをパート単位で組み立てます。
- 抽出結果は `visualCopy` と `layoutPlan` を優先し、見出し・要点・数値・オブジェクト配置を構造化して保存できます。
- 単体再生成も同じ抽出ロジックを再利用します。
- 最終プロンプトのレイアウト指示は `aspectRatio` に応じて横長 / 正方形 / 縦長へ切り替えます。
- スタイル参照画像が指定されている場合は、画像生成時に参照画像として API に渡し、プロンプト上でも「内容はコピーせずデザイン文法だけを合わせる」よう指示します。
- 画像生成バッチは最大3並列で実行し、一部失敗した場合は成功分を保存したうえで失敗パートを画面に表示します。

## 7. ドキュメントと実装の優先順位

- 仕様が食い違う場合は、必ず実装コードを正として扱ってください。
- docs は実装の説明であり、実装を拘束する古い設計書としては扱いません。

## 8. 開発時フラグ（Electron Main）

- `NEWSVIDEO_OPEN_DEVTOOLS=1` のときだけ DevTools を自動起動します（`electron/main.ts`）。
- `NEWSVIDEO_LOG_LEVEL` で Main 側ログレベルを制御できます（`error|warn|info|debug`）。
- ログ出力は `electron/utils/logger.ts` 経由に統一し、画像生成時はプロンプト本文を出力しません。
