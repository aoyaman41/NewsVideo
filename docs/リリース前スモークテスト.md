# リリース前スモークテスト

このドキュメントは、Public Beta を GitHub Releases に出す前に、最低限そろっているべき動作確認を同じ観点で繰り返すためのチェックリストです。

## 目的

- 配布版の起動可否を確認する
- API キー保存と接続確認が通ることを確認する
- 記事入力から動画出力までの最短フローを確認する
- 保存 / 再読込の破綻がないことを確認する
- リリース可否を判断するための最低限の証跡を残す

## 前提条件

- 対象ビルドは `main` 由来の公開候補版
- 実行環境は `macOS / Apple Silicon (arm64)`
- ネットワーク接続あり
- API キーは以下のどちらかを用意済み

  - 既定設定のまま試す: `Anthropic`、`OpenAI`、`Google`
  - `Google` だけで試す: 事前に `設定 > 生成モデル` で「文章を作るモデル」を `Gemini 3.1 Pro`、「画像を作るモデル」を `Gemini 3.1 Flash Image` に変更

入力データ:

- [サンプル記事](./サンプル記事.md)
- 公開用の見本: [サンプル出力](./サンプル出力.md)

## 実施手順

### 1. 起動確認

- [ ] 設定をすべて消した状態(新規ユーザー)で起動すると「ようこそ」画面が開く
- [ ] 「あとで設定する」で `プロジェクト` 画面に移り、次回の起動では「ようこそ」画面が自動では開かない
- [ ] クラッシュせずにサイドバーの `プロジェクト` と `設定` を往復できる

合格条件:

- 画面が白紙にならない
- 起動直後にブロッカーになるエラーダイアログが出ない

### 2. API キーと設定

- [ ] 「ようこそ」画面(または `設定 > API キー`)で 3 つのキーを貼り付け、「保存して確認」で「使えます」になる
- [ ] わざと誤ったキーを保存すると「使えません」になり、案内と「詳しい内容」が表示される
- [ ] `設定 > 生成モデル` で文章・画像・音声のモデルを選べ、キーが未設定のサービスには「API キーを設定する」の案内が出る
- [ ] `設定 > 詳細設定` で台本と画像の指示のモデルを別々に選べ、`GPT-5.6 Sol / Terra / Luna` が表示される
- [ ] GPT-5.6 系を選ぶと、推論の強さに `最大` が表示され、`最小` は表示されない
- [ ] `Claude Opus 5.5` を選ぶと、思考の深さに `低 / 中 / 高 / 非常に高い / 最大` が表示され、新規設定では `中(既定)` が選ばれている
- [ ] `設定 > 詳細設定` で「進め方」と「1 回の予算の上限」を変えると、記事画面の「詳細設定」にも同じ値が出る
- [ ] 設定画面上部の状態が `保存済み` になり、アプリを再起動しても選択(進め方と予算を含む)が保持される
- [ ] `設定 > 読み辞書` で表記と読みを登録でき、再起動後も残る

合格条件:

- 保存済みのキーは入力欄に表示されない(「保存済み」とだけ表示される)
- モデルを変更した場合も `保存済み` まで戻る

### 3. サンプル入力での最短フロー

- [ ] 「新しい動画を作る」で種類を選び、プロジェクトを 1 件作成する
- [ ] `記事` 画面に [サンプル記事](./サンプル記事.md) のタイトル、出典、本文を貼り付ける
- [ ] 公開用サンプルと近い形で比較したい場合は、「詳細設定」の `シーン数` を `3` に変更する
- [ ] 「費用の目安」が表示されることを確認し、「おまかせで作る」を押す
- [ ] 生成中に `プロジェクト` 画面や `設定` 画面へ移っても、画面上部の進み具合が表示され続ける

合格条件:

- 記事の必須項目エラーが出ない
- 画面上部の進み具合が進む
- 途中で致命的なエラーが出ない

### 4. 生成完了の確認

- [ ] 完成すると通知が出て、画面上部に「動画ができました」と「今回の費用の目安」が表示される
- [ ] 「動画を見る」で動画画面が開く
- [ ] 工程ナビ(記事 → 台本 → 画像 → 音声 → 動画)がすべて完了の表示になる
- [ ] GPT-5.6 系・`Claude Opus 5.5` を選んだ場合、台本と画像の指示が選択したモデルで作られ、費用の目安が 0 にならない
- [ ] `画像` 画面と `音声` 画面で、各シーンに画像と音声がそろっている
- [ ] 生成中に「停止」を押すと止まり、「続きから」で再開できる
- [ ] わざとキーを外した(誤ったキーにした)状態で生成すると、止まった理由の案内から設定画面の API キーを開ける
- [ ] `画像` 画面で「画像を作る」「N 枚目を作り直す」「指示を足して作り直す」が使え、画像がないシーンがあるときは「足りない画像を作る」でまとめて作れる
- [ ] `音声` 画面で、音声がないシーンがあるときは「足りない音声を作る」でまとめて作れる
- [ ] 作業画面(台本・画像・音声・動画)でエラーが起きたとき、例外の文ではなく、原因と次の操作が表示され、元の文は「詳しい内容」で見られる

合格条件:

- 生成内容の文言一致までは求めない
- 各ステップで最低 1 件以上の成果物ができ、画面遷移が継続できることを確認する

### 5. 出力と保存 / 再読込

- [ ] `動画` 画面で「シーン N をプレビュー」を押すと、進み具合が表示されてからそのシーンが再生できる
- [ ] 「字幕を入れる」の ON/OFF と「締めの画面」(見出し・ひとこと)を変えて「動画を書き出す」を押すと、書き出した動画に反映される
- [ ] 書き出しの進み具合が細かく進み、「止める」で止められる(止めたときにエラーの表示は出ない)
- [ ] 別のプロジェクトで自動生成が動画を書き出している間に、このプロジェクトの動画画面に、その進み具合が出ない
- [ ] 出力先の `.mp4` が存在することを確認する
- [ ] アプリを閉じて再起動し、同じプロジェクトを「開く」で開ける
- [ ] 再読込後も記事、各工程の状態、動画出力情報が残っている

合格条件:

- プロジェクト一覧に「完成」と表示される
- 再起動でプロジェクトが壊れない

## リリース判定

- 必須項目が 1 つでも落ちたら公開しない
- 外部 API 側の一時障害が疑われる場合でも、少なくとも 1 回は再試行して結果を残す
- 失敗がアプリ側か外部要因か判別できない場合は、Issue を起こしてから公開判断を行う

## 失敗時に残す情報

- 配布版のバージョン
- 実行した日時
- 使った API 構成 (`OpenAI + Google AI` / `Google AI only`)
- 台本と画像の指示のモデル、思考の深さ(推論の強さ)
- 費用の目安と、完成時に表示された今回の費用の目安
- 失敗した画面と操作
- エラーの案内と「詳しい内容」の文、または画面のスクリーンショット
- 生成途中まで進んでいる場合は、そのプロジェクト名

## 制作ワークスペースの追加検証

- 記事と台本の入力直後に画面を切り替え、ウィンドウを閉じて復元する
- APIなしサンプルの3シーンと音声を再生する
- 横・縦・正方形の字幕・見出し・棒グラフと前後動画・締め画面を確認する
- `npm run test:native` の4実出力テストを実行する（macOS CIとリリースビルドで必須）
- 一覧の「…」メニューからごみ箱へ移動・復元し、素材込みバックアップを元データなしで復元する
- 診断JSONに本文・キー・パスが含まれないことを確認する
- 生成停止、画面再読込、アプリ再起動後の再開を確認し、二重課金・素材消失がないか見る
- 未署名/未notarizeの配布方針は従来どおり。Developer IDや証明書の準備なしに署名済みと表示しない
