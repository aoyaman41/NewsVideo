## 1. 見積もりの補正
提案書 §1.1 の原因を直す。
- `shared/project/generationEstimate.ts`
  - 画像の想定トークン: 「モデル × サイズ × 品質」の表にする。GPT Image 2.5 の 4K / high は実測 3,336 出力トークン。まだ実測のない組み合わせ(FHD / 2K、medium など)は、公式情報とこの実測から推定し、推定である旨をコメントに残す
  - Gemini の画像: 公式の 1 枚あたりの単価で計算する
  - 台本: 出力 450 / シーン程度。画像プロンプト: 入力は記事 + 1,500、出力 1,500 程度。実測の分布(提案書 §1.1)に合わせて調整してよい
  - 画面に出す値: 幅ではなく「約 $X(多くて $Y)」とし、上限は ×1.3
- `electron/jobs/engine.ts`: 予算の予約を、補正後の見込み × 1.5 にする(今は × 2)。予算の既定 $5 は据え置く
- 手元の実データ(`b3e9698d-…`・飯田橋のプロジェクトなど)で、補正後の見積もりと実績を比べるテストかスクリプトを用意し、結果を報告に書く

## 2. 費用の表示
- **生成中の「今回の費用」**: 進捗バー(`src/components/job/JobProgressBanner.tsx`)に、実行中は「今回 約 18 円($0.12)・見込み 約 75 円($0.50)」の形で表示する。完了時は「今回かかった費用(推定)」として、台本・画像・音声の内訳を付ける(「目安」という表現はやめる)
- **通貨**: 円とドルを併記する。為替レートは AppSettings に保存し、設定画面で変更できるようにする(既定 150 円/ドル)。金額の整形は 1 か所の関数にまとめ、全画面で使う(記事画面の見積もりも同じ形にする)
- **削除しても残る台帳**:
  - Main 側で、usage を記録するたびに全体の台帳にも追記する(例: userData 直下のファイル)。記録する項目は、日時・プロジェクト ID と名前・プロバイダ・用途・モデル・トークン数・計算した金額程度。記事本文や API キーなどは入れない
  - 既存の全プロジェクトの usage から、初回に 1 回だけ台帳を作る。二重登録しないよう、usage の ID で重複を防ぐ
  - 設定画面に「使った費用」の区分を作り、月別・サービス別(Anthropic / OpenAI / Google)の合計を表示する。各社の請求画面へのリンクも置く。「アプリ内の記録から計算した推定で、実際の請求とは異なることがあります」と注記する

## 3. 詳細設定の初期値の修正
- **秒数から文字数への換算**: `electron/ipc/ai.ts:701` の「秒数 × 4 文字」を、実測の 5.3 文字/秒にする(定数にまとめる)
- **用途ごとの数値の一元化**: `shared/project/purposes.ts` と `shared/project/presentationProfile.ts` の食い違い(解説は 30 秒と 40 秒、ショートは 20 秒と 15 秒、シーン数の予備値は 5 と 3)を解消し、`purposes.ts` を正にする。記事画面の「用途」の選択肢(4 種)と作成画面(3 種)の不一致も整理する。判断に迷えば報告する
- **ショート動画**: 5 シーン × 10〜12 秒にする(ユーザー決定)
- **映像のビットレート**: 8M 固定をやめ、解像度と fps から自動で決める(目安は YouTube の推奨。1080p30 で 8Mbps、1080p60 で 12Mbps、4K30 で 35〜45Mbps)。ユーザーが明示的に保存した値の扱い(自動に切り替えるか、保存値を優先するか)は、互換性を考えて設計し、報告に書く
- **GPT Image の 4K**: 設定画面の画像の大きさで、4K に「実験的」と表示する

## 4. 新しい動画の既定値
提案書 §1.4 の設計で実装する。
- AppSettings に `newProjectDefaults` を追加する(zod で部分的に検証し、正規化で既定値を補う)。**設定保存時に全プロジェクトの generationConfig を書き換える仕組み(`electron/ipc/settings.ts` の `generationKeys`)には入れない**
- 項目: 最初に選ばれている用途、画像の雰囲気と補足、話し方と補足、締めのひとこと、締めの画面、出典の表示、進め方と予算(M4-C で AppSettings に移したキーを、この区分から設定できるようにする)。縦横比の既定(今は効いていない `defaultAspectRatio`)もここで扱う
- 適用: `project:create` で、用途の profile に既定値を重ねる。重ねる関数を `purposes.ts` に 1 つ作り、テストを付ける。用途の性格を決める項目(縦横・秒数・シーン数)は用途を優先し、見た目と締めの項目は既定値を優先する
- 既存のプロジェクトは変えない。「まだ台本がない動画にも適用」ボタンを置く
- 設定画面に「新しい動画」区分を作り、「これから作る動画に使います。作成済みの動画は変わりません」と注記する
- 記事画面の詳細設定は「この動画だけ」変える場所にする。今は、記事画面で進め方と予算を変えると既定値まで書き換わる(`src/pages/ArticleInputPage.tsx` の 219-223 行付近)ので、その回だけに効くよう直す。既定値と違う項目に印を付け、「既定に戻す」を置く

## 6. 統合時の確認項目(メインループ + ユーザー)
- 記事画面の見積もりと、生成後の実績の差が ±30% 以内に収まること(3 シーンと 5 シーン)
- 予算 $5 のまま、4K でも予算超過で止まらないこと
- 生成中の進捗バーに、今回の費用が円とドルで出ること。完了時に内訳が出ること
- 設定画面の「使った費用」に、既存のプロジェクトを含む月別・サービス別の合計が出ること。プロジェクトを削除しても合計が減らないこと
- 「約 90 秒」のニュース動画が、実際にも 80〜100 秒程度になること。ショートが 5 シーンになること
- 「新しい動画」の既定値が新規作成に反映され、既存のプロジェクトが変わらないこと
