## 1. ユーザー決定事項(2026-09-26)

- GPT Image 2.5 の **Sunburst と Flare の両方**を画像モデルに追加する

メインループ判断:
- 画像モデルの既定値(`gemini-3.1-flash-image-preview`)は**変えない**
- 品質は既存の GPT Image 2 と同じ挙動のまま(2.5 で追加された `xhigh` / `max` を選ぶ UI は今回は作らない。必要ならフォローアップ)。※訂正: 本番の IPC(`electron/ipc/image.ts`)は `quality: 'auto'` ではなく、解像度に応じて fhd=`low` / 2k=`medium` / 4k=`high` を送る。`auto` なのは本番で使われていない `generateOpenAIImage` だけだった
- 公式のモデルIDはエイリアス(日付なし)を使う

## 2. モデル仕様(OpenAI 公式、2026-09 時点)

| モデルID | 表示名 | 位置づけ | 既定スナップショット |
|---|---|---|---|
| `gpt-image-2.5-sunburst` | GPT Image 2.5 Sunburst | 品質重視。GPT Image 2 より高画質 | `gpt-image-2.5-sunburst-2026-09-08` |
| `gpt-image-2.5-flare` | GPT Image 2.5 Flare | 速度重視。画質は GPT Image 2 と同程度 | `gpt-image-2.5-flare-2026-09-08` |

- 料金(1M トークン、両モデル共通、GPT Image 2 と同額): テキスト入力 $5 / テキストのキャッシュ入力 $1.25 / 画像入力 $8 / 画像のキャッシュ入力 $2 / 画像出力 $30。テキスト出力は課金なし
- エンドポイント: `v1/images/generations` と `v1/images/edits`(※訂正: 本アプリはスタイル参照画像があるとき `images.edit` も使う)
- サイズ: 幅・高さとも 16 の倍数、アスペクト比 1:3〜3:1、一辺の最大 3840px、総画素数 655,360〜8,294,400。2560x1440 を超える解像度は実験的扱い(GPT Image 2 と同じ制約)
- quality: `low` / `medium` / `high` / `xhigh` / `max` / `auto`(既定は `auto`)
- output_format: `png`(既定)/ `jpeg` / `webp`
- 参照: https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst 、 https://developers.openai.com/api/docs/models/gpt-image-2.5-flare 、 https://developers.openai.com/api/docs/guides/image-generation

## 3. 実装範囲

1. **モデル定数**(`shared/constants/models.ts` の画像区画)
   - `OPENAI_IMAGE_MODELS` に 2 モデルを追加し、ラベルも追加する。並び順は `gpt-image-2.5-sunburst`、`gpt-image-2.5-flare`、`gpt-image-2`
   - `getImageModelProvider` / `isOpenAIImageModel` が新モデルを `openai` と判定することをテストで確認する
2. **画像生成**(`electron/utils/openaiImage.ts`、`electron/ipc/image.ts`)
   - `generateOpenAIImage` がモデル名を `'gpt-image-2'` に固定しているので、モデルを引数で受け取るようにする。呼び出し元は選択中の `imageModel` を渡す
   - サイズ計算(`getOpenAIImageDimensions`)は 3 モデル共通で使える。コメントの「GPT Image 2」を「GPT Image 2 / 2.5」に直す
   - 生成メタデータ(`metadata.generation.model`)と usage に、実際に使ったモデルIDが記録されることを確認する(`'gpt-image-2'` の固定がほかにないかを `grep -rn "gpt-image-2'" electron src shared` で洗い出す)
3. **使用量・コスト**(`src/utils/cost.ts`、`src/utils/usage.ts` の画像区画)
   - `DEFAULT_OPENAI_IMAGE_RATES` に 2 モデルを追加する(§2 の料金)
   - `usage.ts` の `details.model || (provider === 'openai' ? 'gpt-image-2' : ...)` は、model が記録されていない古いレコード用の代替値なので `gpt-image-2` のままにする
4. **UI**(`src/pages/SettingsPage.tsx` ほか)
   - `settings.imageModel === 'gpt-image-2'` のときだけ出している OpenAI 画像モデルの説明文を、`isOpenAIImageModel(settings.imageModel)` の条件にする
   - 画像モデルの選択肢は定数から自動生成されるか確認する。ImageManagePage などにモデル名の固定表示があれば対応する
   - OpenAI の API キーが未設定のまま OpenAI の画像モデルを選んだときの警告が、新モデルでも出ることを確認する
5. **ドキュメント**: 画像モデルを列挙している docs を更新する(`grep -rn "GPT Image 2\|gpt-image-2" docs README.md` で洗い出す)。`docs/データ取り扱い.md` の送信先の記述も確認する
6. **テスト**(既存テストのパターンに合わせる。`src/utils/newModels.test.ts`、`electron/utils/openaiImage.test.ts`、`electron/ipc/image.test.ts` が参考になる)
   - models: 新モデル、ラベル、プロバイダ判定
   - openaiImage: 選んだモデルIDがリクエストの `model` に入ること、サイズと quality が変わらないこと
   - image IPC: 新モデルを選ぶと OpenAI 経路で生成され、メタデータと usage にそのモデルIDが記録されること
   - cost: 2 モデルの料金計算(GPT Image 2 と同額になること)

## 4. 非スコープ

- 画像編集(edits)エンドポイント、inpainting
- quality の選択 UI(`xhigh` / `max`)
- 画像モデルの既定値の変更
- 既存プロジェクトの画像の再生成

## 5. 統合時の確認項目(メインループ + ユーザー)

- Sunburst / Flare それぞれでテスト用プロジェクトの画像を 1 枚ずつ生成し、指定した縦横比・解像度で保存されること
- 画像のメタデータと使用量にモデルIDが正しく記録され、概算コストが 0 にならないこと
- GPT Image 2 と Gemini 画像モデルの回帰確認
