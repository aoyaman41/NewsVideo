## 0. 共通ルール

1. **最初に worktree のベースを確認する。** `git log --oneline -1` がこの指示書のコミットでなければ、未変更の状態のまま `git reset --hard feature/ux-speed-export-models` を実行し、そのあと `npm ci` を実行する
2. **コミット・push・デプロイはしない。** 納品物は「未コミットの worktree + 完了報告」
3. **指示書外の設計判断が必要になった場合、または解決できない問題に直面した場合は、勝手に進めず停止してメインループへ報告する**
4. **実 API を叩かない。** API キーやシークレットを print・ログ出力しない。ユーザーデータ(`~/Library/Application Support/newsvideo`)は読み取りのみ可
5. **デザインの基準**は `src/styles/tokens.css`(CSS 変数 `--nv-*`)と共通コンポーネント `src/components/ui/`。古い slate / indigo / `rounded-2xl` の方式は廃止済みなので使わない。新しい色や角丸を勝手に増やさない
6. **保存データの互換性**: 画面から機能を外しても、スキーマ(`shared/project/schema.ts` など)の項目は消さない。zod は未知の項目を捨てるので、スキーマから消すと既存プロジェクトのデータが次の保存で失われる
7. **用語を統一する**: 画面上の呼び方は「記事」「台本」「シーン」「画像」「音声」「動画」。「パート」「スクリプト」「原稿」「カット」は使わない(コード上の識別子はそのままでよい)。英語の混在(Before/After、ending など)、専門用語(プロンプト、TTS、CTA、fps、dBFS、ジョブ ID など)は、初心者向けの画面には出さない。どうしても必要なら「詳細設定」の中だけにする
8. 完了条件: `npm run typecheck` / `npm run lint` / `npm test` / `npm run audit:licenses` がすべて通ること
9. 完了報告に含めるもの: 変更ファイル一覧、画面ごとの変更点(変更前 → 変更後)、削除した機能と残した機能、主要な設計判断、テスト結果、未解決事項、統合時にメインループとユーザーが操作して確認すべき項目、worktree のパスとブランチ名、reset 後の HEAD
10. 画面の確認に `npm run dev` などでアプリを起動しない(メインループが開発モードのアプリを起動中のため)。見た目の確認は統合時に行う

## 1. ユーザー決定事項(2026-09-26)

- 既定の構成は「台本・画像プロンプト = Claude Opus 5.5 / 画像 = GPT Image 2.5 Sunburst / 音声 = Gemini 3.8 Flash TTS」。初回に必要な API キーは Anthropic・OpenAI・Google の 3 つ
- 初回起動時は、案内に沿って API キーを設定する(構成の選択はさせない)。キーがなくてもサンプルは試せる
- 自動生成は全自動が既定(確認のために止めない)。「確認しながら」は詳細設定の選択肢として残す
- 機能の削減はメインループに一任された。判断は次の表のとおり

| 機能 | 扱い |
|---|---|
| テキストインポート(`FileImport.tsx`、依存の `mammoth`) | 削除 |
| 出典の記録・根拠と確認状態・素材の権利(`SourceRecords` / `EvidenceReview` / `AssetRights`) | 画面から削除 |
| ジョブ履歴・ジョブ ID(`JobHistory`) | 画面から削除。エラーが起きたときの案内は残す |
| 予算の入力 | 詳細設定へ移す |
| 字幕 | ON/OFF だけを動画画面に残す。細かい編集は削除 |
| 読み(辞書) | **残す**。設定画面にまとめる(日本語の読み間違いを直す唯一の手段のため)。シーンごとの読み・間の編集は削除 |
| 音声の実測(dBFS など)、波形の詳細、ファイルパスの表示 | 削除(波形は折りたたみで残してよい) |
| 制作記録の表(プロジェクト一覧) | 削除(記録そのものは継続) |
| 素材の更新状態(`AssetReview`) | 古くなったときだけ、短い案内で表示 |
| 文字数を入力して分割(SceneStudio) | 削除 |
| 公開前チェック | 動画画面上部の表示と統合 |
| 複製・テンプレート・アーカイブ・バックアップ・ごみ箱 | プロジェクト一覧の「…」メニューにまとめる |

## 2. 目指す導線

```
初回起動 → ようこそ画面
  ・3 つのキー(Anthropic / OpenAI / Google)を 1 画面で、取得先リンク・入力・接続テストまで案内
  ・「あとで設定する」「サンプルを見る」を用意(キーなしでもサンプルを開ける)
プロジェクト一覧 →「新しい動画を作る」
  → ① 記事を貼る(タイトルと本文が主。用途などは控えめに。費用の見積もりを表示)
  →「おまかせで作る」(主ボタンは 1 つだけ。止まっているジョブがあるときだけ「続きから」)
  → ② 生成中: どの画面にいても、上部に進捗バーが常に出る(工程ごとの進み具合・停止ボタン)
  → ③ 完成: 通知と「動画を見る」ボタン → 動画画面で確認・書き出し
  └ 各シーンを直したいときは、台本・画像・音声の各画面で「作り直す」(詳細編集)
```

## 3. 担当区画と実装範囲

### 3.1 M4-A: 導線・設定・レイアウト
**担当ファイル**: `src/App.tsx`、`src/components/layout/`、`src/pages/ProjectListPage.tsx`、`src/pages/ArticleInputPage.tsx`、`src/components/article/`、`src/pages/SettingsPage.tsx`、新規コンポーネント(`src/components/onboarding/` など)、`src/stores/` のうち上記に必要なもの、`package.json`(`mammoth` の削除)、`docs/クイックスタート.md`・`README.md`・`docs/FAQとトラブルシュート.md` などの手順書
1. **初回セットアップ**: §2 のようこそ画面。キー未設定の検知(既存の `settings:hasApiKey`)。設定画面からも同じ案内を開き直せるようにする
2. **自動生成の入口の統一**(記事画面):
   - 生成系のボタンを「おまかせで作る」1 つにする。「続きから」は、止まっているジョブがあるときだけ出す
   - 「下書きを保存」ボタンは不要なら消す(自動保存があるため)
   - 詳細設定(記事画面の 8 項目)は折りたたみにまとめる。予算と「確認しながら」モードもそこへ移す
3. **常駐の進捗表示**:
   - レイアウトの上部に、自動生成の進捗バーを出す。`job:statusChange` イベントと `project.job` を読み、`project.job.progress` があれば工程ごとの進み具合(`{ done, total }`、動画は `percent`)を表示する。なければ `stage` の文字で代替する(`progress` は M2 が実装中。形は `shared/project/jobs.ts` の `jobProgressSchema`)
   - 停止ボタン、完了時の通知と「動画を見る」、失敗時の分かりやすい案内も出す
4. **エラー表示**:
   - 例外の文字列をそのまま出さない。既知のエラー(API キー未設定・認証失敗・レート制限・Claude の拒否・書き出しの競合など)は、原因と次の操作(「設定を開く」「別のモデルで再実行」「もう一度試す」)をボタン付きで示す
   - 詳細は折りたたみで見られるようにする
5. **設定画面の再構成**:
   - 「API キー」「生成モデル」「動画」「読み辞書」「詳細設定」に分ける
   - 生成モデルは、用途別(台本・画像プロンプト/画像/音声)に `SELECTABLE_*` の一覧から選ぶ
   - 「思考の深さ」などの専門的な設定、同時実行数、fps、ビットレート、読み上げ開始の間、確認モード、予算、診断は「詳細設定」へ
   - 台本の生成モデルが「音声」タブにある問題を解消する
   - Gemini TTS で効いていない設定(話速)は表示しない
6. **プロジェクト一覧**: 作成フォームを分かりやすくし、「…」メニューへの集約と制作記録の表の削除を行う
7. **レイアウト**:
   - 保存状態の帯・ヘッダー・工程ナビの 3 段が常に上部を占める問題を解消する
   - 保存状態の表示を 1 か所にする
   - 工程ナビの用語を §0-7 に揃え、累計費用の常時表示をやめる(見積もりと完了後の合計に絞る)
8. **手順書**: クイックスタートと README の手順を新しい画面に合わせて書き直す。存在しないボタンの記述を消す。スクリーンショットの差し替えは統合時にメインループが行うので、差し替えが必要な箇所の一覧を報告に書く

### 3.2 M4-B: 作業画面の整理・デザイン統一
**担当ファイル**: `src/pages/ScriptEditPage.tsx`、`src/pages/ImageManagePage.tsx`、`src/pages/AudioManagePage.tsx`、`src/pages/VideoManagePage.tsx`、`src/components/script/`、`src/components/image/`、`src/components/audio/`、`src/components/common/`、`src/components/ui/`、`src/styles/`
1. **台本画面**: 出典・根拠・権利・シーンごとの読み・間・グラフィックの詳細・音声の実測・文字数での分割を削除する。1 シーンあたりのセクション数を減らす。自動保存なのに「保存」ボタンがある箇所を整理する
2. **画像画面**:
   - 「プロンプトを生成」と「画像を生成」の 2 段階を「画像を作る」1 つにまとめる(既存の IPC を順に呼ぶ)
   - プロンプトの編集は「指示を足して作り直す」に置き換える
   - 「1 シーン 1 枚」の表示と、実際の書き出しが複数の画像を使うことの食い違いを直す(候補を選ぶと全カットが 1 枚に置き換わる問題も含む)
   - 無効なボタンには理由を表示する
3. **音声画面**: エンジン名が「Gemini TTS」に固定表示されている問題、「更新が必要」が緑で表示される問題を直す。波形は折りたたみにし、ファイルパスを消す
4. **動画画面**:
   - 字幕の ON/OFF をここに置く
   - HTTP ヘッダを含むデバッグ用の文字列をエラー表示に出さない
   - 公開前チェックを上部の表示と統合する
   - 素材が足りないときは、書き出しボタンを押す前に理由を示す
   - M1 で入れた「自動生成の実行中は書き出しとプレビューを無効にする」処理は残す
5. **デザイン統一**:
   - gray 系の色(7 ファイル・33 か所)を tokens に置き換える
   - 色指定のない `rounded border`(12 か所)に枠線の色を付ける
   - 角丸を tokens の 2 種類に揃える
   - `<details>` やチェックボックス、表の見た目を揃える
   - 余白と文字の大きさで情報の優先度が分かるようにする
6. **アクセシビリティ**: マウスを乗せたときだけ出る削除ボタンをキーボードでも使えるようにする。素のボタンにフォーカス表示(`nv-focus-ring`)を付ける。ウィンドウの最小幅 1200px で 3 カラムが崩れる問題を直す

## 5. 統合時の確認項目(メインループ + ユーザー)

- 設定をすべて消した状態(新規ユーザー)で起動し、ようこそ画面から 3 つのキーを設定して、最初の動画まで迷わずに進めること
- 記事を貼って「おまかせで作る」を押したあと、別の画面に移っても進捗が見え、完成の通知から動画を開けること
- わざとキーを外して、エラーの案内から設定画面に行けること
- 削除した機能が画面から消え、既存のプロジェクトが問題なく開けること
- 読み辞書が設定画面で使えること。字幕の ON/OFF が動画画面で使えること
