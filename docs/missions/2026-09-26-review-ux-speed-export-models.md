# 改善提案: UX・生成速度・動画書き出し・最新モデルへの最適化

- 作成日: 2026-09-26(ベースは main の e9ec653 = PR #94 のマージ後)
- 依頼(ユーザー、2026-09-26):
  1. デザイン・UI・UX が初めて触る人に分かりづらい。テキストインポートなどの余計な機能を減らすことも検討してほしい
  2. 並列化できるのに直列の箇所があり、動画生成全体に時間がかかりすぎている
  3. 最後の動画書き出しが、自動生成でも止まってしまう
  4. 各仕組み(設定項目・プロンプトのスタイル)が最新モデルに最適化されているかを調査・検討したい
- 進め方: 4 領域を読み取り専用のサブエージェントで並行調査 → メインループがコードと公式ドキュメントで主要な主張を検証 → この提案書でユーザーが方針を決定 → ミッションごとに指示書を作って実装を発注

## 1. 調査結果の要点

### 1.1 緊急: 既定の画像モデルが提供終了済み(検証済み)
- `gemini-3.1-flash-image-preview`(既定値、`shared/constants/models.ts`)と `gemini-3-pro-image-preview` は **2026-06-25 に提供終了**。後継は GA 版の `gemini-3.1-flash-image` / `gemini-3-pro-image`(https://ai.google.dev/gemini-api/docs/deprecations)
- 手元のデータでも、Gemini 画像モデルで最後に生成できたのは 2026-03-29。設定を変えていない新規ユーザーは画像生成に失敗する見込み

### 1.2 動画書き出しが止まる原因(検証済み・再現済み)
- `electron/ipc/video.ts:1020` が、画面側のリビジョンと保存済みの最新リビジョンの**完全一致**を要求している
- メインプロセスが画面に通知しないままリビジョンを上げる箇所が 2 つある: プレビュー時の metrics 更新(`video.ts:982-987`)と、書き出し開始時の出力設定の保存(`video.ts:1063`)
- そのため「プレビュー → 書き出し」という推奨手順どおりに操作すると、2 回目以降の書き出しで毎回「保存後にプロジェクトが変更されました」で失敗する。自動生成の動画工程中に手動で書き出しを押した場合も、待たされた後に失敗する
- 自動生成の動画工程には進捗表示がほぼなく(4K60・3 パートで約 2 分半)、止まって見える。動画を作る処理そのものは壊れていない
- 再現テスト(リポジトリ外、6 件): `scratchpad/video/render-stall.repro.test.ts`

### 1.3 生成が遅い原因(コードで検証済み、時間は実測と推定)
- 自動生成ジョブ(`electron/jobs/engine.ts`)が、画像工程・音声工程ともパートごとの `for` ループで 1 件ずつ処理している。同時実行数の設定(既定 2、上限 4)は自動生成では効いていない
- 以前(2026-03 の画面側の実装)は画像と音声を並行、音声は 5 並列だった。PR #93 でジョブエンジンを Main に移したときに直列になった
- 3 パートの実例(Claude Opus 5.5 / GPT Image 2.5 Sunburst 4K / 3.8 Flash TTS)の正味時間の内訳は次のとおり。合計は約 345 秒
  - 台本 7 秒
  - 画像プロンプト 60 秒
  - 画像 104 秒
  - 音声 26 秒
  - 動画 148 秒
- 動画は 4K60 の設定で 3 回エンコードしている。調査担当の実測では、最終出力は実際には 60fps になっておらず(平均 15.8fps)、映像・音声のビットレート設定も反映されていない
- 見込み: 並列化と 30fps 化で約 345 秒 → 約 110 秒(約 −68%、推定)

### 1.4 UX の主な問題(コードで確認)
- **自動生成の入口と進み方が分かりにくい**
  - 記事画面に生成系のボタンが 5 個あり、初回でも「続きから」と表示される
  - 既定の「確認しながら」モードでは 2 回止まるが、止まったことは記事画面の小さな欄にしか出ない
  - 台本画面から「続ける」ことができない。完了の通知もない
  - クイックスタートに書かれた「記事から動画まで自動生成」ボタンが、実際の画面にない
- **初回のセットアップ**: 既定の構成では OpenAI と Google の 2 つの API キーが必要。初回の案内も、キー未設定の検知もない
- **分かりにくい停止とエラー表示**
  - 予算を指定していると、料金未確定の記録が 1 件でもあるたびに「予算確認」で止まる。抜け方が画面に書かれていない
  - エラーは例外の文字列がそのまま表示され、設定画面への導線もない
- **テキストインポート**: 失敗しても反応がなく、本文を確認なしで上書きする。削除しても保存データへの影響はない
- **上級者向け機能が主導線に出ている**: 出典・根拠・権利・字幕・読み・音声実測・ジョブ履歴など
- **画像画面の表示と実際の処理の食い違い**: 画像画面は「1 パート 1 枚」と表示しているが、実際の書き出しは複数カットを使う。候補を選ぶとカットが 1 枚に置き換わる
- **デザイントークンからの逸脱と用語の揺れ**
  - gray 系の色が 33 か所、色指定のない枠線が 12 か所
  - 「シーン / パート」「台本 / スクリプト」が混在している

### 1.5 最新モデルへの最適化の主な指摘(公式ドキュメント準拠)
- **画像の画質**
  - 解像度 FHD のとき、GPT Image は `quality: low`、Gemini は 1K で生成しているため、文字がぼやける
  - Gemini 3 Pro Image は 1K と 2K が同じ価格
- **画像内の文字の指示**: 描いてよい文字の指示が 3 か所に分かれていて矛盾している。公式の推奨は「描く文言を引用符で正確に指定し、それ以外の文字は描かない」
- **テキスト生成の設定**
  - Claude の effort の既定値 `high` は、公式の「medium から始めて比較する」と逆
  - Gemini 3.1 Pro に temperature を送っているが、公式は既定値のままを強く推奨している
  - 画像プロンプトの抽出で、3 社とも構造化出力を使っていない
- **3.8 TTS のスタイル指示**: 長い命令文を渡している。公式は `"calm, clear news narration"` のような短い記述子を推奨。3.8 は台本中の `<>` を声の演出タグとして解釈する
- **プロンプトキャッシュが効かない原因**: 自動生成ジョブの経路(`ai:generateImagePromptForTarget`)では、キャッシュの指定が一度も付かない
- **モデルの選択肢が多すぎる**
  - テキスト 9 種、TTS 5 種
  - 旧モデル(GPT-5.2 / 5.4 / 5.5、TTS 3.1 / 2.5)は、公式に後継がある
- **原価表示の漏れ**: Gemini の thinking トークンを計上していない。OpenAI のキャッシュ書き込みの割増も計上していない

## 2. 提案するミッション構成

| ミッション | 内容 | 規模 | 依存 |
|---|---|---|---|
| **M1 緊急修正** | Gemini 画像を GA 版の ID に置換し、保存済みの preview ID を自動で読み替える。書き出しの判定をリビジョンから書き出す内容に変え、通知漏れを直し、競合時に 1 回だけ再読込して再試行する。ジョブ実行中は手動の書き出しを無効化し、ジョブの動画工程の進捗を表示する | S〜M | なし(最優先) |
| **M2 生成の高速化** | ジョブの並列化(台本の後に全パートのプロンプトを並列にし、できたパートから画像へ進め、音声も並行させる)。その前提として、実行中の処理の記録・予算の予約・キャンセル時の扱いを並列に対応させる。プロバイダごとの同時実行枠と、画像の分あたり枚数の制御。動画の fps 既定値とビットレートの反映。動画工程の細かい進捗 | M | M1 の後 |
| **M3 モデル最適化** | 画像内の文字ルールの統一と、解像度と品質の対応付けの見直し。画像プロンプト抽出を 3 社とも構造化出力に移行。Gemini の temperature を撤去。Claude の effort を用途別の既定値に。キャッシュが効く構成への変更。3.8 TTS の短いスタイルと `<>` の処理。旧モデルを選択肢から外す(保存済みの値は維持)。原価計上の漏れの修正 | M | M1 の後。M2 とは並行可 |
| **M4a UX: 導線** | 初回のセットアップ案内(API キー・構成選択)。自動生成の入口を 1 つに統一。全画面に常駐する進捗表示と、確認待ち・完了・エラーの案内。エラー表示の改善 | M〜L | M2 のジョブ状態の形に依存 |
| **M4b UX: 整理** | 機能の削減と「詳細編集」への移動。設定画面の再構成(品質プリセットと詳細設定)。用語の統一。デザイントークンへの統一とアクセシビリティ。クイックスタート・README・スクリーンショットの更新 | M〜L | M3 のモデル整理の後 |

- 進める順序の案: M1 → (M2 ∥ M3 ∥ M4a) → M4b。統合と E2E は、ミッションごとにユーザー同席で行う
- 既存の別件: v1.1 の古いプロジェクトが旧プリセット値 `news_broadcast` のために読めない問題は、M1 に含める(提案済みの別タスクがまだ開始されていなければ)

## 3. ユーザーに判断してほしい点(推奨つき)

| # | 論点 | 選択肢 | 推奨 |
|---|---|---|---|
| Q1 | GA 化後の既定の画像モデル | Gemini 3.1 Flash Image(GA) / GPT Image 2.5 Flare | Gemini 3.1 Flash Image(Google のキー 1 本で始められ、安価) |
| Q2 | 動画のフレームレート | 30fps を既定にする / 60fps を維持(追加の改修 M が必要) | 30fps(動画工程が約 3 倍速く、今の実際の出力より滑らか) |
| Q3 | 自動生成の停止回数 | 全自動 / 台本の確認で 1 回だけ止まる / 現状の 2 回 | 台本の確認で 1 回だけ(書き出しには API 料金がかからない) |
| Q4 | FHD の画質とコスト | 画質を上げる(Gemini は 2K、GPT は medium。1 枚 +$0.03 程度〜) / 現状維持 | 画質を上げる |
| Q5 | 機能の削減 | テキストインポートは削除、報道向け・上級機能は「詳細編集」へ移す / すべて削除 / 現状維持 | テキストインポートは削除し、ほかは「詳細編集」へ(保存データは互換を保つ) |
| Q6 | 初心者向けの既定構成 | 初回に選ばせ、Google 1 本をおすすめ表示 / Google 1 本に固定 / 現状(OpenAI + Google) | 初回に選ばせ、Google 1 本をおすすめ表示 |

メインループが推奨で進める点(異論があれば変更する):
- Claude の effort は、台本 `medium`、抽出とコメント反映 `low` を既定にし、2〜3 記事で品質を比べて確定する(2026-09-26 に決めた「既定 high」を見直す)
- プロバイダごとの同時実行数は、テキスト 4 / 画像 2〜3(OpenAI は 5 枚/分の制御付き)/ TTS 4 を既定にする。並列中に 1 件失敗したら新しい処理は始めず、実行中のものは完了させて成功分を保存する
- Opus 5.5 の拒否時は、引き続きエラー表示のみにする(bio の分類器が追加されたことは記録しておく)
- GPT Image の 4K(公式に experimental)は、実際に 3840x2160 で生成できたので現状のまま残す
- 旧モデルは選択肢から外すが、保存済みの設定値は読めるように残す

## 5. ユーザー決定事項(2026-09-26)

| # | 決定 |
|---|---|
| Q1 | 既定の画像モデルは **GPT Image 2.5 Sunburst**(推奨の Gemini ではなく)。提供終了した Gemini の preview ID は GA 版に置き換え、保存済みの値は自動で読み替える |

| Q3 | 自動生成は **全自動**(確認のために止めない)を既定にする。「確認しながら」モードは詳細設定の選択肢として残す |
| Q4 | FHD の画質を**上げる**(Gemini は 2K、GPT Image は medium) |
| Q5 | 機能の削減は、**テキストインポートに加えて上級機能も画面から削除**する(保存データの項目は残す)。対象の最終リストは M4b の指示書作成時にユーザーに確認する(特に「読み(辞書)」は日本語の読み間違いを直す手段なので要確認) |
| Q6 | 初回起動時は、**案内に沿って API キーを設定**する(構成の選択はさせない)。キーがなくてもサンプルは試せるようにする |
| Q7 | 既定のテキストモデル(台本・画像プロンプト)は **Claude Opus 5.5**。既定の構成は「文章 Anthropic・画像 OpenAI・音声 Google」となり、**初回に必要な API キーは 3 つ**になる |

Claude の effort は用途別の 2 つの設定に分け、既定値は**台本・画像プロンプトとも medium**(当初案の「画像プロンプトは low」をユーザーが medium に変更)。

メインループの判断(§3 の推奨どおり): プロバイダごとの同時実行数、失敗時の扱い、拒否時はエラー表示のみ、GPT Image の 4K は維持、旧モデルは選択肢から外す(保存値は維持)。注意: Claude が既定になるため、感染症などの報道で bio 分類器による拒否が起きうる。拒否時のエラー文で「別のモデルで再実行」へ誘導する(M4a)
